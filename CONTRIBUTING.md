# Contributing

sentry-axi follows the [AXI](https://github.com/kunchenguid/axi) design principles. Contributions should preserve those principles - token-efficient TOON output, minimal default schemas, structured errors with recovery suggestions, no interactive prompts, contextual next-step hints.

**Human-authored pull requests targeting `main` must be raised through [`no-mistakes`](https://github.com/kunchenguid/no-mistakes).**
A GitHub Actions check (`Require no-mistakes`) fails PRs whose body is missing the signature no-mistakes writes; the release and dependency bots are exempt.

## Workflow

1. Create a branch and make your changes.
2. Initialize the gate once (`no-mistakes init`), then push through it instead of pushing to `origin`:

   ```sh
   git push no-mistakes
   ```

   The pipeline reviews, tests, and builds in an isolated worktree, then opens the PR for you.
3. Run the local verification pass before pushing:

   ```sh
   npm run build
   npm test                                  # unit suite - no token needed
   npx tsx scripts/build-skill.ts --check    # generated skill is current
   (cd bench && npx vitest run test)         # bench harness unit tests
   ```

3. For changes touching the API client, issue/event parsing, or the sentry-cli delegation layer, also run the live suite against a real Sentry org:

   ```sh
   npm run test:e2e                          # needs SENTRY_AUTH_TOKEN (and an org/project)
   ```

4. Open a PR with a conventional-commit-style title (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`).

## Repo conventions

- Node 20+, TypeScript, ESM-only (`.js` extensions in relative imports).
- Unit tests in `test/*.test.ts` (Vitest); live tests in `e2e/*.e2e.test.ts`, gated so they skip without a token.
- Do not hand-edit `skills/sentry-axi/SKILL.md` - it is generated by `npm run build:skill` from `src/skill.ts`; update the generator instead.
- Keep `skills/sentry-axi/` in the npm package `files` list so releases include the installable Agent Skill.
- API response parsers are written against the captured fixtures in `test/fixtures/api-responses.md`. If a Sentry API response shape changes, re-capture it, update the fixture, and adjust the parser and its tests in the same change.
- New commands must follow the AXI checklist: per-command `--help` entry in `COMMAND_HELP`, TOON output, structured `SentryAxiError` with suggestions on every failure path, idempotent mutations (repeat = no-op success), `--session`/`--org`/`--project` compatibility, and a `test/` case for argument parsing.

## Benchmark changes

The harness in `bench/` replicates [axi's bench-browser](https://github.com/kunchenguid/axi) methodology. When adding tasks or conditions:

- Tasks that only one condition can perform must declare `applicable_conditions` so other conditions are reported N/A, never failed.
- Update `bench/README.md`'s fairness caveats when a change affects comparability.
- Regenerate published results only from a full `matrix` run; per-run artifacts (agent output, judge output, grades) land under `bench/results/` for auditability.
